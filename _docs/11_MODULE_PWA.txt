# GESTION DES SESSIONS HORS LIGNE

## OBJECTIF

Le mode hors ligne est une extension d'une session déjà authentifiée.

Il ne remplace jamais le système d'authentification du serveur.

Le serveur reste toujours la source de vérité.

---

# PREMIÈRE CONNEXION

La première connexion doit obligatoirement être effectuée avec une connexion Internet.

Flux :

```text
Utilisateur
        ↓
Authentification serveur
        ↓
Vérification du compte
        ↓
Téléchargement :
    • Profil utilisateur
    • Permissions
    • Company
    • Store
    • Paramètres
    • Données nécessaires
        ↓
Création d'une session locale sécurisée
```

À partir de ce moment, l'utilisateur peut continuer à travailler hors ligne.

---

# CONNEXION HORS LIGNE

Une connexion hors ligne est autorisée uniquement si :

✓ une session locale valide existe ;

✓ la session n'a pas expiré ;

✓ l'utilisateur ne s'est jamais déconnecté ;

✓ l'appareil est reconnu.

Sinon :

```text
Connexion Internet obligatoire.
```

---

# EXPIRATION DE SESSION

Une session hors ligne possède une durée maximale.

Exemple :

```text
7 jours
```

Au-delà :

```text
Connexion Internet obligatoire.
```

Cette vérification permet de contrôler :

* l'état du compte ;
* les permissions ;
* l'abonnement ;
* les paramètres de sécurité.

---

# DÉCONNEXION

La déconnexion est toujours autorisée.

Elle ne nécessite pas Internet.

Lors de la déconnexion :

Supprimer :

✓ session locale

✓ token

✓ informations d'authentification

✓ clés de session

✓ données temporaires

Ne pas supprimer :

✓ ventes non synchronisées

✓ brouillons

✓ opérations en attente

✓ file de synchronisation

---

# VENTES NON SYNCHRONISÉES

Les ventes réalisées hors ligne ne doivent jamais être supprimées lors d'une déconnexion.

Chaque vente possède un état.

Exemple :

```text
PENDING_SYNC

SYNCING

SYNCED

FAILED
```

Les ventes restent enregistrées localement jusqu'à leur synchronisation complète avec le serveur.

---

# AVERTISSEMENT AVANT DÉCONNEXION

Si des opérations non synchronisées existent :

Afficher :

```text
Des opérations sont en attente de synchronisation.

Si vous vous déconnectez maintenant,
elles resteront enregistrées sur cet appareil
jusqu'à leur synchronisation.

Voulez-vous continuer ?
```

Boutons :

* Annuler
* Se déconnecter

---

# CHANGEMENT D'UTILISATEUR

Les opérations hors ligne appartiennent toujours
à l'utilisateur qui les a créées.

Chaque opération locale contient notamment :

```text
company_uuid

store_uuid

user_uuid

device_uuid

status
```

Un autre utilisateur ne doit jamais voir
les opérations d'un précédent utilisateur.

---

# BLOCAGE DE CHANGEMENT D'UTILISATEUR

Par mesure de sécurité :

Si des ventes non synchronisées existent
pour un utilisateur,

aucun autre utilisateur ne peut ouvrir une nouvelle session
sur le même appareil.

Afficher :

```text
Des ventes non synchronisées sont encore présentes sur cet appareil.

Veuillez synchroniser les données avant de changer d'utilisateur.
```

---

# SYNCHRONISATION

Lorsque la connexion revient :

```text
Connexion Internet

↓

Synchronisation automatique

↓

Validation serveur

↓

Base de données

↓

Statut = SYNCED
```

Une fois la synchronisation validée,
la file d'attente locale est nettoyée.

---

# ÉCHEC DE SYNCHRONISATION

Si une synchronisation échoue :

* conserver les données ;

* afficher un message explicite ;

* permettre une nouvelle tentative.

Aucune donnée ne doit être perdue.

---

# RÈGLES DE SÉCURITÉ

Le mode hors ligne ne doit jamais permettre de contourner :

✓ l'authentification

✓ les permissions

✓ le scope

✓ l'isolation multi-tenant

✓ les règles métier

✓ les validations serveur

Le serveur reste toujours la source de vérité.

---

# POINTS CRITIQUES À SURVEILLER

✓ Première connexion obligatoirement en ligne.

✓ Ne jamais stocker le mot de passe.

✓ Chiffrer les données sensibles stockées localement.

✓ Utiliser uniquement des UUID.

✓ Toutes les données locales doivent contenir :

* company_uuid
* store_uuid
* user_uuid
* device_uuid

✓ Ne jamais supprimer les ventes non synchronisées.

✓ Bloquer le changement d'utilisateur si des ventes sont en attente.

✓ Toujours informer l'utilisateur de l'état :

* Hors ligne
* Synchronisation
* Succès
* Échec

✓ Journaliser toutes les synchronisations.

✓ Tester les scénarios suivants :

* coupure Internet pendant une vente ;
* fermeture de l'application ;
* batterie vide ;
* reconnexion après plusieurs jours ;
* changement de mot de passe ;
* désactivation d'un employé ;
* changement de permissions ;
* changement de magasin ;
* changement d'appareil.
