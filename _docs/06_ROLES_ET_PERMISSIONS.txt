===========================================================
ROLES ET PERMISSIONS
PLATEFORME SAAS DE GESTION COMMERCIALE
===========================================================

VERSION : 1.0

OBJECTIF

Définir les rôles de la plateforme ainsi que les rôles
des entreprises (tenants) et leurs permissions.

===========================================================
1. ARCHITECTURE DES PERMISSIONS
===========================================================

User
 ↓
Membership
 ↓
Company
 ↓
Role
 ↓
Permission

Les rôles ne doivent pas être codés en dur dans
l'application, à l'exception éventuelle de SUPER_ADMIN.

Toutes les autorisations doivent être pilotées par
des permissions stockées en base de données.

===========================================================
2. RÔLES DE LA PLATEFORME
===========================================================

SUPER_ADMIN

Responsabilités :

- gérer toutes les entreprises
- gérer les abonnements
- gérer les plans tarifaires
- suspendre une entreprise
- voir les statistiques globales
- gérer le support
- accéder aux journaux techniques

Permissions :

can_manage_companies
can_manage_subscriptions
can_manage_plans
can_suspend_companies
can_view_global_reports
can_manage_support
can_view_system_logs

-----------------------------------------------------------

SUPPORT_ADMIN

Responsabilités :

- assister les clients
- consulter certaines informations techniques
- réinitialiser des comptes
- consulter les logs

Permissions :

can_view_companies
can_reset_accounts
can_view_support_logs
can_manage_tickets

===========================================================

===========================================================
4. RÔLES PERSONNALISÉS
===========================================================

Une entreprise doit pouvoir créer des rôles
personnalisés.

Exemples :

- Superviseur
- Assistant
- Responsable Pharmacie
- Responsable Boutique
- Responsable Caisse

Les rôles personnalisés sont composés de permissions.

6. UTILISATEURS MULTI-MAGASINS
===========================================================

Un utilisateur peut appartenir à :

- plusieurs entreprises ;
- plusieurs magasins.

Le champ :

store_id

permet de limiter l'accès d'un employé
à un magasin spécifique.

===========================================================
7. RÈGLES DE SÉCURITÉ
===========================================================

Ne jamais vérifier les permissions dans React uniquement.

Le backend Django est la source de vérité.

Toutes les API doivent vérifier :

1. utilisateur actif
2. entreprise active
3. rôle actif
4. permissions nécessaires

===========================================================
8. PRINCIPES DE CONCEPTION
===========================================================

Les permissions sont plus importantes que les rôles.

Les rôles ne sont qu'un regroupement de permissions.

Le système doit être :

- flexible ;
- extensible ;
- multi-tenant ;
- sécurisé.
