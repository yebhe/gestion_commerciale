Oui. C’est **un ajout**, donc **aucune des règles précédentes n’est supprimée ou modifiée**. On ajoute simplement le niveau **ENTREPÔT** sous le STORE.

La hiérarchie devient :

```text
TENANT
   ↓
STORE
   ↓
ENTREPÔTS
   ↓
EMPLACEMENTS
   ↓
STOCK
```

Et on ajoute les règles suivantes à la version précédente :

```txt
============================================================
AJOUT — GESTION MULTI-ENTREPOTS PAR STORE
============================================================

1. Un STORE peut posséder plusieurs ENTREPOTS.

2. Les entrepôts appartiennent à un STORE.

3. Un entrepôt appartient donc indirectement à un TENANT.

4. Un store peut fonctionner avec :
   - un seul entrepôt
   - plusieurs entrepôts
   - aucun entrepôt selon les besoins du store.

5. Chaque entrepôt peut représenter :
   - un dépôt principal
   - un dépôt secondaire
   - un dépôt régional
   - une réserve
   - une zone de stockage
   - un centre logistique.


============================================================
HIERARCHIE ACTUALISEE
============================================================

TENANT
   |
   +---- STORE A
   |       |
   |       +---- ENTREPOT A1
   |       |       |
   |       |       +---- EMPLACEMENTS
   |       |
   |       +---- ENTREPOT A2
   |       |       |
   |       |       +---- EMPLACEMENTS
   |       |
   |       +---- ENTREPOT A3
   |               |
   |               +---- EMPLACEMENTS
   |
   +---- STORE B
           |
           +---- ENTREPOT B1
           |
           +---- ENTREPOT B2


PRINCIPE :

TENANT
   ↓
STORE
   ↓
ENTREPOT
   ↓
EMPLACEMENT
   ↓
STOCK


============================================================
INDEPENDANCE DES ENTREPOS
============================================================

6. Chaque entrepôt possède son propre stock.

7. Le stock de l'entrepôt A1 est différent du stock
   de l'entrepôt A2.

8. Deux entrepôts du même store peuvent contenir
   des quantités différentes du même produit.

9. Exemple :

   Store A

   Entrepôt A1 :
      Produit X = 500

   Entrepôt A2 :
      Produit X = 200

   Stock total du Store A :
      Produit X = 700


============================================================
STOCK PAR ENTREPOT
============================================================

10. Le stock doit pouvoir être consulté par :

    - store
    - entrepôt
    - emplacement
    - produit
    - variante
    - lot.

11. Le système doit pouvoir afficher :

    Stock Entrepôt A1
    Stock Entrepôt A2
    Stock Entrepôt A3

    ainsi que :

    Stock total du Store.


============================================================
EMPLACEMENTS DANS UN ENTREPOT
============================================================

12. Un entrepôt peut posséder plusieurs emplacements.

13. Exemple :

    Entrepôt A1
       |
       +---- Rayon A
       |      +---- A01
       |      +---- A02
       |
       +---- Rayon B
       |      +---- B01
       |      +---- B02
       |
       +---- Zone froide
              +---- F01
              +---- F02

14. Le stock peut donc être suivi jusqu'au niveau
    de l'emplacement.

15. Exemple :

    Produit X :

    Entrepôt A1
       A01 = 50
       A02 = 100

    Total Entrepôt A1 = 150.


============================================================
TRANSFERT ENTRE ENTREPOTS DU MEME STORE
============================================================

16. Un transfert entre deux entrepôts appartenant au
    même store est autorisé.

17. Le transfert entre entrepôts est une opération
    métier explicite.

18. Un transfert entre entrepôts ne doit PAS être considéré
    comme une nouvelle vente ou un achat.

19. Il doit générer :

    ENTREPOT SOURCE
        ↓
    SORTIE DE STOCK

    ENTREPOT DESTINATION
        ↓
    ENTREE DE STOCK


============================================================
EXEMPLE DE TRANSFERT INTER-ENTREPOTS
============================================================

20. Situation initiale :

    Store A

    Entrepôt A1 :
       Produit X = 100

    Entrepôt A2 :
       Produit X = 20

21. Transfert de 30 unités :

    A1 → A2

22. Après transfert :

    Entrepôt A1 :
       Produit X = 70

    Entrepôt A2 :
       Produit X = 50

23. Stock total du Store A reste :

       70 + 50 = 120

24. Le transfert ne détruit donc aucune quantité.

25. Il ne fait que déplacer la quantité d'un entrepôt
    vers un autre.


============================================================
REGLE IMPORTANTE — STOCK TOTAL DU STORE
============================================================

26. Le transfert entre deux entrepôts du même store
    ne doit pas modifier le stock total du store.

27. Exemple :

    Avant :
       A1 = 100
       A2 = 50
       Total = 150

    Transfert :
       A1 → A2 = 30

    Après :
       A1 = 70
       A2 = 80
       Total = 150


============================================================
TRANSFERT ENTRE EMPLACEMENTS
============================================================

28. Un transfert peut également être effectué entre
    deux emplacements du même entrepôt.

29. Exemple :

    A1 / Rayon A / A01
          ↓
    A1 / Rayon B / B01

30. Le stock total de l'entrepôt reste inchangé.


============================================================
NIVEAUX DE TRANSFERT
============================================================

31. Le système peut donc gérer plusieurs niveaux :

    Niveau 1 :

    Entrepôt A1
        ↓
    Entrepôt A2

    Niveau 2 :

    Entrepôt A1 / Emplacement A
        ↓
    Entrepôt A1 / Emplacement B

    Niveau 3 :

    Store A / Entrepôt A1
        ↓
    Store B / Entrepôt B1


============================================================
TRANSFERT ENTRE STORES
============================================================

32. Les règles précédentes sur les transferts entre stores
    restent entièrement valables.

33. Un transfert peut être :

    STORE A
       ENTREPOT A1
          ↓
       ENTREPOT B1
       STORE B

34. Le store source diminue son stock.

35. Le store destination augmente son stock.

36. Le stock total des deux stores est conservé,
    hors pertes/casses/ajustements éventuels.


============================================================
DISTINCTION DES TRANSFERTS
============================================================

37. Le système doit distinguer :

    A. Transfert intra-entrepôt

       Emplacement A → Emplacement B

    B. Transfert inter-entrepôts

       Entrepôt A1 → Entrepôt A2

    C. Transfert inter-stores

       Store A / Entrepôt A1
          →
       Store B / Entrepôt B1


============================================================
TRANSFERT INTER-ENTREPOTS — STATUTS
============================================================

38. Un transfert inter-entrepôts peut avoir :

    - brouillon
    - demandé
    - validé
    - préparé
    - expédié
    - en transit
    - reçu
    - annulé
    - rejeté.

39. Pour un transfert physique entre deux entrepôts,
    le statut "en transit" peut être utilisé.

40. Exemple :

    Entrepôt A1 :
       Stock physique = 100

    Transfert :
       30 unités vers A2

    Après expédition :

       A1 = 70
       Transit = 30
       A2 = 0

    Après réception :

       A1 = 70
       Transit = 0
       A2 = 30


============================================================
REGLE DE COHERENCE
============================================================

41. L'entrepôt source et l'entrepôt destination doivent
    appartenir au même store pour un transfert
    inter-entrepôts.

42. Exemple valide :

    Store A
       ├── Entrepôt A1
       └── Entrepôt A2

    A1 → A2


43. Exemple invalide pour un transfert inter-entrepôts :

    Store A
       └── Entrepôt A1

    Store B
       └── Entrepôt B1

    A1 → B1

44. Ce cas doit être traité comme un TRANSFERT INTER-STORE,
    et non comme un transfert inter-entrepôts.


============================================================
STOCK PHYSIQUE PAR NIVEAU
============================================================

45. Le système doit permettre de calculer :

    Stock emplacement
       ↓
    Stock entrepôt
       ↓
    Stock store
       ↓
    éventuellement stock global tenant.


============================================================
EXEMPLE COMPLET
============================================================

46. Tenant A

    Store A

       Entrepôt A1
          ├── Rayon A
          │    ├── A01 = 50
          │    └── A02 = 30
          │
          └── Rayon B
               └── B01 = 20

          Total A1 = 100


       Entrepôt A2
          ├── Rayon C
          │    └── C01 = 40
          │
          └── Rayon D
               └── D01 = 60

          Total A2 = 100


       STOCK TOTAL STORE A = 200


============================================================
TRANSFERT DANS CET EXEMPLE
============================================================

47. Transfert :

    Entrepôt A1
       ↓
    Entrepôt A2

    Quantité = 30


48. Après transfert :

    Entrepôt A1 = 70
    Entrepôt A2 = 130

    Stock total Store A = 200


============================================================
REGLE SUR LES PRODUITS
============================================================

49. L'ajout des entrepôts ne modifie PAS la règle
    fondamentale des produits.

50. Le produit appartient toujours au STORE.

51. Il n'appartient pas directement à l'entrepôt.

52. L'entrepôt contient le STOCK du produit.

53. Donc :

    PRODUCT
       ↓
    STORE
       ↓
    STOCK
       ↓
    WAREHOUSE
       ↓
    LOCATION


54. Cela signifie qu'un même produit du store peut être
    présent dans plusieurs entrepôts.


============================================================
EXEMPLE PRODUIT + MULTI-ENTREPOTS
============================================================

55. Store A possède :

    Produit X

56. Stock :

    Entrepôt A1 = 100
    Entrepôt A2 = 50
    Entrepôt A3 = 200

57. Produit X reste UN SEUL produit du Store A.

58. Il possède plusieurs quantités de stock réparties
    dans plusieurs entrepôts.


============================================================
REGLE SUR LES VARIANTES
============================================================

59. Les variantes restent liées au produit du store.

60. Chaque variante peut avoir du stock dans plusieurs
    entrepôts.

61. Exemple :

    T-shirt Noir M

       Entrepôt A1 = 20
       Entrepôt A2 = 15

       Total = 35


============================================================
REGLE SUR LES LOTS
============================================================

62. Un lot peut également être réparti dans plusieurs
    entrepôts.

63. Exemple :

    Lot LOT-2026-001

       Entrepôt A1 = 100
       Entrepôt A2 = 50

       Total = 150


============================================================
REGLE SUR LES RESERVATIONS
============================================================

64. Les réservations peuvent être associées à un
    entrepôt précis lorsque nécessaire.

65. Exemple :

    Entrepôt A1 :

       Physique = 100
       Réservé = 20
       Disponible = 80

66. Le système peut également calculer le disponible
    au niveau du store.


============================================================
REGLE SUR LES INVENTAIRES
============================================================

67. L'inventaire peut être réalisé :

    - au niveau du store
    - au niveau d'un entrepôt
    - au niveau d'un emplacement
    - au niveau d'un produit
    - au niveau d'un lot.

68. Un inventaire d'entrepôt ne doit pas modifier
    directement les autres entrepôts.

69. Un inventaire de l'entrepôt A1 concerne uniquement
    le stock d'A1.

70. Les ajustements générés doivent être liés au bon
    entrepôt et emplacement.


============================================================
REGLE SUR LES MOUVEMENTS DE STOCK
============================================================

71. Chaque mouvement de stock doit pouvoir identifier
    son entrepôt.

72. Lorsque nécessaire, il doit également identifier
    l'emplacement.

73. Un mouvement doit donc pouvoir contenir :

    - tenant
    - store
    - warehouse
    - location
    - product
    - variant
    - lot
    - type
    - quantity
    - stock before
    - stock after
    - user
    - date
    - source document
    - reason


============================================================
REGLE DE TRAÇABILITE
============================================================

74. Il doit être possible de répondre à :

    "Pourquoi le stock du Produit X dans l'Entrepôt A1
     est-il actuellement de 70 ?"

75. Le système doit pouvoir retrouver :

    - stock initial
    - achats
    - ventes
    - retours
    - transferts entrants
    - transferts sortants
    - inventaires
    - ajustements
    - pertes
    - casses
    - autres mouvements.


============================================================
REGLE ABSOLUE SUR LES TRANSFERTS
============================================================

76. Un transfert physique ne doit jamais être traité
    comme une vente.

77. Il ne doit pas créer de chiffre d'affaires.

78. Il ne doit pas créer artificiellement une marge.

79. Il ne doit pas créer un nouvel achat.

80. Il déplace uniquement une quantité de stock.

81. Le système doit conserver son historique.


============================================================
REGLE DE CONSERVATION DU STOCK
============================================================

82. Pour un transfert interne sans perte :

    Stock avant transfert
    =
    Stock après transfert


83. Exemple :

    A1 = 100
    A2 = 50

    Total = 150

    Transfert 30 :

    A1 = 70
    A2 = 80

    Total = 150


============================================================
REGLE DE COHERENCE HIERARCHIQUE
============================================================

84. Un emplacement appartient à un entrepôt.

85. Un entrepôt appartient à un store.

86. Un store appartient à un tenant.

87. Donc :

    LOCATION
       ↓
    WAREHOUSE
       ↓
    STORE
       ↓
    TENANT


88. Le backend doit empêcher :

    Location du Warehouse A
    utilisée avec Warehouse B.

89. Le backend doit empêcher :

    Warehouse du Store A
    utilisé dans une opération du Store B.

90. Le backend doit empêcher :

    Warehouse du Tenant A
    utilisé dans une opération du Tenant B.


============================================================
ARCHITECTURE FINALE DU STOCK
============================================================

91. La gestion des stocks devient :

    TENANT
       ↓
    STORE
       ↓
    WAREHOUSES
       ↓
    LOCATIONS
       ↓
    PRODUCT / VARIANT / LOT
       ↓
    STOCK
       ↓
    STOCK MOVEMENTS


============================================================
92. REGLE FINALE — AUCUNE AUTRE REGLE N'EST SUPPRIMEE
============================================================

93. L'ajout du multi-entrepôt ne modifie PAS :

    - le modèle multi-tenant
    - l'indépendance des stores
    - la propriété du produit par le store
    - les prix propres au store
    - les clients propres au store
    - les fournisseurs propres au store
    - les ventes propres au store
    - les achats propres au store
    - les variantes
    - les lots
    - les réservations
    - les inventaires
    - les mouvements de stock
    - les transferts entre stores
    - l'audit
    - les permissions
    - la sécurité multi-tenant
    - le fonctionnement offline
    - la synchronisation
    - la gestion des conflits
    - la traçabilité.


============================================================
PRINCIPE FINAL MIS A JOUR
============================================================

TENANT
   ↓
STORES INDEPENDANTS
   ↓
CHAQUE STORE POSSEDE SES PROPRES ENTREPOTS
   ↓
CHAQUE ENTREPOT POSSEDE SES PROPRES EMPLACEMENTS
   ↓
LES PRODUITS APPARTIENNENT AU STORE
   ↓
LE STOCK EST REPARTI ENTRE LES ENTREPOTS
   ↓
LES MOUVEMENTS SONT TRACABLES
   ↓
TRANSFERTS POSSIBLES :

   EMPLACEMENT → EMPLACEMENT

   ENTREPOT → ENTREPOT
   DU MEME STORE

   STORE A / ENTREPOT A
       ↓
   STORE B / ENTREPOT B


============================================================
REGLE D'OR
============================================================

Un STORE peut avoir plusieurs entrepôts.

Chaque entrepôt possède son propre stock.

Un même produit du store peut être présent dans plusieurs
entrepôts.

Le transfert entre deux entrepôts du même store est autorisé.

Ce transfert déplace le stock sans modifier le stock total
du store.

Le transfert entre deux stores reste une opération distincte
et suit toutes les règles précédemment définies.

AUCUNE REGLE PRECEDENTE N'EST SUPPRIMEE OU REMPLACEE.

============================================================
FIN DE L'AJOUT MULTI-ENTREPOTS
============================================================
```
