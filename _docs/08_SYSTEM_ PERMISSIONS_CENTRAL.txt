# SYSTÈME DE PERMISSIONS CENTRAL
# SAAS DE GESTION COMMERCIALE MULTI-TENANT


=========================================================
1. PRINCIPE FONDAMENTAL
=========================================================

Toute l'application doit être construite autour :

- des Permissions ;
- du Scope (COMPANY ou STORE) ;
- de l'isolation par UUID.

Les permissions contrôlent :

✓ l'accès aux modules
✓ l'affichage des menus
✓ les widgets du dashboard
✓ les boutons d'action
✓ les routes
✓ les API
✓ les opérations autorisées


Les rôles ne sont PAS utilisés dans le code métier.

Les rôles sont uniquement des groupes de permissions.


❌ Incorrect :

if role == "Manager"


✅ Correct :

hasPermission("sales.create")


La règle de sécurité est :

Permission
+
Scope
+
Company UUID
+
Store UUID (si nécessaire)
=
Autorisation


=========================================================
2. ISOLATION MULTI-TENANT
=========================================================

L'application possède deux niveaux d'isolation.


---------------------------------------------------------
NIVEAU 1 : COMPANY
---------------------------------------------------------

Le scope COMPANY représente l'entreprise complète.

Identifiant utilisé :

company_uuid


Exemples de rôles :

- Owner
- Company Admin
- Accountant Global


Accès :

✓ tous les magasins de la compagnie
✓ tous les employés
✓ tous les rapports
✓ tous les paramètres
✓ toutes les données de la compagnie


---------------------------------------------------------
NIVEAU 2 : STORE
---------------------------------------------------------

Le scope STORE représente un magasin spécifique.

Identifiant utilisé :

store_uuid


Exemples :

- Manager
- Cashier
- Stock Manager
- Store Accountant


Accès :

✓ uniquement son magasin
✓ uniquement son stock
✓ uniquement ses ventes
✓ uniquement sa caisse
✓ uniquement ses rapports


Un utilisateur STORE ne peut jamais accéder à un autre magasin.


=========================================================
3. RÈGLE DES UUID ET DU SCOPE
=========================================================

Toutes les ressources doivent être liées à :

company_uuid


Les ressources liées à un magasin doivent contenir :

store_uuid


Exemple :

products

- uuid
- company_uuid
- name


inventory

- uuid
- company_uuid
- store_uuid
- quantity


sales

- uuid
- company_uuid
- store_uuid


---------------------------------------------------------
RÈGLE OWNER
---------------------------------------------------------

Le Owner possède un scope :

COMPANY


Il peut utiliser toutes les permissions STORE.

Cependant, chaque action STORE doit obligatoirement recevoir
un store_uuid.


Exemple :

Owner :

Permission :

inventory.adjust


Demande :

company_uuid = ABC

store_uuid = XYZ


Vérification :

XYZ appartient bien à ABC ?


Oui :

✓ Autorisé


Non :

✗ Refusé


---------------------------------------------------------
RÈGLE UTILISATEUR STORE
---------------------------------------------------------

Un utilisateur STORE possède un store_uuid attribué.


Exemple :

Manager :

store_uuid = XYZ


Demande :

inventory.adjust

store_uuid = ABC


Résultat :

✗ Refusé

=========================================================

✓ unique
✓ modulaire
✓ dynamique


Affichage basé uniquement sur :

- permissions ;
- scope ;
- company_uuid ;
- store_uuid.

✗ un menu

✗ un module

✗ un bouton

✗ une statistique


sans permission.
