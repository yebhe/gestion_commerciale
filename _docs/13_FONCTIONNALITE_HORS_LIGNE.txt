# FONCTIONNALITÉS DISPONIBLES HORS LIGNE

## OBJECTIF

Le mode hors ligne ne doit pas être limité au module POS.

L'objectif est de permettre au commerce de continuer à travailler normalement même en cas de coupure Internet.

Le serveur reste toujours la source de vérité.

Toutes les opérations effectuées hors ligne sont synchronisées automatiquement dès le retour de la connexion.

---

# SYNCHRONISATION DES CRUD

Toutes les opérations CRUD effectuées hors ligne doivent être placées dans une file d'attente.

Exemple :

```text
CREATE Produit

↓

IndexedDB

↓

PENDING_SYNC

↓

Internet retrouvé

↓

Synchronisation

↓

Validation serveur

↓

SYNCED
```

Même principe pour :

* UPDATE

* DELETE (Soft Delete)

---

# FILE D'ATTENTE DES OPÉRATIONS

Chaque opération doit être enregistrée indépendamment.

Structure recommandée :

```text
operation_uuid

company_uuid

store_uuid

user_uuid

device_uuid

entity_type

entity_uuid

operation_type

payload

status

created_at

synced_at

retry_count
```

---

# TYPES D'OPÉRATIONS

```text
CREATE

UPDATE

DELETE
```

Le serveur traite ensuite chaque opération dans l'ordre chronologique.

---

# GESTION DES CONFLITS

Avant toute synchronisation, le serveur vérifie :

✓ que la ressource existe toujours ;

✓ que l'utilisateur possède toujours les permissions ;

✓ que le magasin est toujours autorisé ;

✓ que la ressource n'a pas été modifiée de manière incompatible.

En cas de conflit :

* conserver les données locales ;

* afficher un message explicite ;

* permettre une nouvelle tentative ou une résolution.

Aucune donnée ne doit être perdue automatiquement.

---

# RÈGLES DE SÉCURITÉ

Toutes les opérations hors ligne doivent continuer à respecter :

✓ l'authentification locale ;

✓ les permissions ;

✓ le scope ;

✓ l'isolation multi-tenant ;

✓ les validations métier.

Le mode hors ligne ne doit jamais permettre de contourner les règles de sécurité.

---

# POINTS CRITIQUES À SURVEILLER

✓ Toujours utiliser des UUID.

✓ Chaque opération doit contenir :

* company_uuid

* store_uuid (si nécessaire)

* user_uuid

* device_uuid

✓ Les opérations doivent être traitées dans leur ordre de création.

✓ Les suppressions doivent être réalisées via Soft Delete.

✓ Ne jamais perdre une opération non synchronisée.

✓ Les rapports hors ligne sont des estimations locales et ne remplacent pas les rapports officiels du serveur.

✓ Toutes les synchronisations doivent être historisées dans l'audit.

✓ Le serveur reste toujours la source de vérité.

✓ Les validations serveur ont toujours priorité sur les données locales.

---

# PRINCIPE FINAL

Le mode hors ligne doit permettre à un magasin de continuer son activité sans interruption.

Cependant, toutes les opérations réalisées hors ligne restent provisoires jusqu'à leur validation et leur synchronisation par le serveur.

Le serveur demeure l'unique référence garantissant la cohérence, la sécurité et l'intégrité des données de la plateforme SaaS.
